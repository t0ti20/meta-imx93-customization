How the CM33
comes to life

The Cortex-M33 on i.MX93 is not self-starting. Its journey from a hardware-held CPUWAIT state to executing firmware involves five distinct actors — ROM, SPL, ATF, U-Boot, and Linux — each doing a narrowly scoped piece of the work.

Key Registers

SRC · BLK_CTL · GIC
Register Address Bit(s) What it controls
SRC_GLOBAL_SCR 0x44460010 [0] Release M33 reset. Write 1 in m33_prepare() to deassert hardware reset. M33 is held in CPUWAIT after this.
SRC_M33P_FUNC_STAT 0x444628B4 RST_STAT Polled after SCR write. Set = reset successfully released. m33_prepare() waits on this.
SRC_GLOBAL_GPR9 0x4446009C [31:0] M33 boot address. Written by ATF SMC handler before clearing CPUWAIT. M33 reads its reset vector from this address.
M33_INITSVTOR 0x444F005C [31:7] Secure vector table offset. ATF writes 0 here before kick to clear any ROM override.
M33_CFG 0x444F0060 [2] CPUWAIT. While set, M33 is halted at reset. ATF SMC handler clears this bit to start execution. Also used by m33_is_rom_kicked() to detect ROM-kicked path.
CA55_IRQ_MASK[1] BLK_CTRL_S [6] Masks WDOG1 IRQ at A55 GIC. Set in m33_prepare() — WDOG1 is reserved for M33 reset recovery.

ATF SMC Interface

IMX_SIP_SRC · EL3 → M33

All CPUWAIT manipulation is gated behind an EL3 Secure Monitor Call. Neither U-Boot nor Linux can touch M33_CFG directly — they must go through ATF's imx_src_handler() in plat/imx/imx93/src.c.

arm_smccc_smc(0xC2000005, x1, boot_addr, 0, ...)

Boot Stages

5 actors · 1 M33
ROM · BL1 Silicon ROM EL3 · fixed in silicon

On power-on the hardware holds the CM33 in CPUWAIT via M33_CFG[2]. The A55 ROM reads boot straps and looks for a signed boot container on the boot device.

If the container includes an M33 image at a known offset, ROM may optionally kick the CM33 itself — this is the ROM-kicked path. On normal eMMC/SD boot this does not happen; ROM boots the A55 SPL and leaves M33 halted.

M33: CPUWAIT = 1 · halted
BL2 · SPL Secondary Program Loader EL3 · u-boot SPL

board_init_f() calls m33_prepare() near the end of its init sequence — after DDR is up, PMIC configured, and M33 co-processor clock enabled. This function does not start M33; it only makes TCM safe to use.

  1. 01Guard: m33_is_rom_kicked() reads M33_CFG[2] (0x444F0060) — if already clear, ROM ran M33, skip prepare and return -EPERM.
  2. 02Release M33 hardware reset: setbits_le32(&SRC_GLOBAL_SCR, BIT(0)) at 0x44460010.
  3. 03Poll SRC_M33P_FUNC_STAT (0x444628B4) until RST_STAT is set — confirms reset deasserted.
  4. 04ELE tamper route release: ele_release_m33_trout() — sends ELE_ENABLE_RTC_REQ via MU to EdgeLock Enclave. Required for M33 to pass its internal security check.
  5. 05Mask WDOG1 IRQ at A55 GIC (CA55_IRQ_MASK[1][6]) — WDOG1 is reserved for M33 reset recovery, A55 must not handle it.
  6. 06Enable WDOG1 clock: ccm_lpcg_on(CCGR_WDG1, 1).
  7. 07ELE LP handshake: set lp_handshake[0][6] for M33 reset coordination during low-power transitions.
  8. 08TRDC reconfig (OSCCA builds): trdc_mbc_blk_config(0x44270000, ...) opens MBC1 blocks 0 and 1 for TCM access.
  9. 09TCM ECC init: memset(0x201E0000, 0, 0x40000) — A55 clears 256 KB of TCML to initialize ECC bits. Without this, M33's first code fetch triggers an ECC error.

M33: reset released · CPUWAIT = 1 · TCM clean · not executing
BL31 · ATF EL3 Runtime Firmware EL3 · secure monitor

ATF installs a permanent Secure Monitor Call handler for the M33 lifecycle. No software outside EL3 can write M33_CFG directly — every kick goes through this handler.

When called with x1 = 0x00 (START), the handler executes:

  1. 01Write 0 → M33_INITSVTOR (0x444F005C) — clears any ROM-set secure vector override.
  2. 02Write boot address → SRC_GLOBAL_GPR9 (0x4446009C). If caller passes x2 = 0, writes 0x0FFE0000 (TCML non-secure base from M33's view).
  3. 03Clear M33_CFG[2] (0x444F0060) — this releases CPUWAIT. The CM33 pipeline unfreezes and begins fetching from the reset vector.

M33: CPUWAIT = 0 · executing from reset vector
BL33 · U-Boot Bootloader (optional M33 use) EL2 / EL1 · non-secure

U-Boot provides two commands for manually loading and starting M33 firmware from the boot environment. Both ultimately issue the same ATF SMC call.

  1. —bootaux <addr> [core] — non-secure path. Copies binary to TCM via A55 memcpy, then calls arch_auxiliary_core_up(0, addr) → SMC START.
  2. —bootaux_cntr <addr> [core] — AHAB authenticated path. Validates NXP container signature before copy, then same SMC kick.
  3. —stopaux [core] — issues SMC STOP (0x02) to quiesce M33 via WDOG1 reset path.
Address space note: the address passed to bootaux is in M33's local view. TCML non-secure base = 0x0FFE0000, TCML secure base = 0x1FFE0000. Load a firmware ELF from FAT/ext4 with fatload first, then bootaux $loadaddr.

Linux remoteproc + RPMsg EL1 · non-secure

The Linux remoteproc framework manages the full M33 lifecycle at runtime: load firmware, kick core, exchange messages, and stop/restart. The driver uses the same ATF SMC path — it never writes hardware registers directly.

  1. 01Driver match: fsl,imx93-cm33 (compatible string in imx93.dtsi). Method flag IMX_RPROC_SMC selected at probe.
  2. 02request_firmware() → loads ELF from /lib/firmware/imx/ (Zephyr demo or SOF).
  3. 03Parse ELF resource table at 0x2021E000 — discovers vring locations, memory carveouts, RPMsg channels.
  4. 04Copy ELF segments to TCM / DDR per resource table PT_LOAD entries.
  5. 05Call arm_smccc_smc(0xC2000005, 0x00, boot_addr, 0, ...) → ATF clears CPUWAIT.
  6. 06Wait fsl,startup-delay-ms = 500 ms for M33 to write its resource table announcement.
  7. 07RPMsg virtio transport comes up over MU1 mailboxes. Userspace sees /dev/rpmsg* endpoints.
